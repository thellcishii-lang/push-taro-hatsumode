# Push-taro 初詣

神社の初詣シーズン専用のプッシュ通知 × クーポン基盤。土台は Push-taro EVENT
（push-taro-event）で、初詣の決定事項（2026-11-18）に合わせて作り替えた。

## 製品の形

- 契約者＝神社、参拝者＝来場者、出店者＝露店・授与所等の出店者（EVENTの3ロールを継承）。
- 1契約で同時に最大3件までイベントを仕込める（EVENTの MAX_CONCURRENT_EVENTS=3 を継承）。
- シーズンモデル：イベント期間は「12月開始可〜1月31日終了」の季節型。月次更新の
  前提はアプリ側に無く、終了処理（最終レポート送信＋登録情報の全消去）は
  終了日の翌日に EVENT の仕組みどおり走る（1月31日終了 → 2月1日に最終処理）。

## 登録は端末認証のみ（タップ認証）

- SMS電話認証は無い。参拝者は匿名認証で端末の識別子（uid）を得て登録する
  （電話番号は一切集めない）。
- memberId = SHA-256('device:' + uid)。クーポン取得・消込、入場用QR取り込み、
  言語別プッシュはすべて端末キーで動く。
- 登録者数による登録ブロックはしない（上限なし）。契約枠（subscriberCap）は
  料金段階のデータとして保持するだけ。

## ブランド

- 表示名は「Push-taro 初詣」。来場者画面の主見出しはイベント名（神社名・行事名）。
- パレット：鳥居の朱（#B3352B／明 #C84A38）を基調に、金茶のグラデーション
  （#F7E8CF→#F0D9AE）と温かみのある墨色（#2A1E17）。EVENT の紫から差し替え。
- 用語：主催者＝神社（契約者）、来場者＝参拝者、出店者＝出店者のまま。

## 注意（デプロイ前）

- apphosting.yaml には EVENT の Firebase プロジェクト値が残っている。
  初詣の Firebase プロジェクト作成（Phase 4）まではデプロイしないこと。
- デプロイ時は Firebase コンソールで匿名認証（Anonymous）の有効化が必要。

## Phase 2 以降の予定（データ構造は妨げない）

- おみくじ（1端末1回限り、記録は毎日リセット対象外の置き場に分離）。
- 元日オーバーレイ（羊の挨拶）：2027-01-01 当日の初回起動時のみ表示し、
  タップで「メェー」→通常画面。1月2日以降の初回起動では出さない。
  表示済みフラグは端末側に保持する。来場者画面の最前面に差し込む前提で、
  Phase 1 の画面構造はオーバーレイ追加を妨げない。
- 簡易タイムテーブル：神社が登録する正月行事（祭典・神楽・祈祷・授与所の
  時間など）を時系列の単一リストで参拝者に見せる。単一神社・単一リストで、
  複数ステージ構造は持たない（それは FES 版の仕事）。events/{eventId} 配下の
  サブコレクションとして追加できる。
- 毎日リセットの初詣ルール（1月1日0時の衝突回避、バッチ上限の引き上げ、
  1月31日24時の最終リセット）。
